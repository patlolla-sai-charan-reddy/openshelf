# SUMMARY.md — OpenShelf autonomous build

## What was built

**OpenShelf — the product index for AI agents.** A complete, static, zero-CSS, zero-backend product index whose consumers are agents/bots (query once instead of crawling hundreds of stores; JSON or HTML), plus an owner-only admin dashboard, in `/Users/sa/retail`:

| File | Purpose |
|---|---|
| `index.html` | Landing for agents: `<h1>OpenShelf</h1>` + "The product index for AI agents. One query, every store.", query form, **Category indexes** `<ul>` (category — products across stores · JSON · search, `<progress value=1>`), **Endpoints for agents** table, footer FTC disclosure. Full meta/OG/audience tags, `<link rel=alternate>` (JSON/OpenAPI/llms.txt), `<link rel=search>`, JSON-LD `WebSite`+`SearchAction` and `DataCatalog` (one `Dataset` per category). List + JSON-LD are pre-rendered from `agents.json` (markers) → no fetch, no layout shift. No emojis. |
| `search.html` | Reads `?q=`, runs the client-side agent, shows `🤖 N agents searched S stores (P products) — M matches for "q"`, 2-column card grid: `<table width=100% cellpadding=6>` → `<td width=50% align=center valign=top>` → 160×160 image over **Brand** / title(≤40) / **price** (HTML attributes only, zero CSS; fits a 375px phone), "Load more" `<a>` (24/batch), zero-results state with agent links. |
| `admin.html` + `admin.js` | Unlinked `noindex` dashboard: PAT in `localStorage` with warning + **Forget token**; multi-file `.json` upload → `validate.js` → row-by-row error `<table>` → preview of first 10 with the *same* `cell()` grid → **Publish** per file via GitHub Contents API (`admin: update shoes.json (N products)`) with commit link → auto-registers new agents in `agents.json` (emoji table) and re-syncs the landing list in `index.html` → status board (products / merchants / last-updated / commit, Plausible link) → **Run bot now** (`workflow_dispatch`). Tested end-to-end against `scripts/mock-github.mjs`. |
| `app.js` (104 lines) | Config (`loader`, `pageSize`, `plausible`, `ga4`, `skimlinks`, `allowLoaderStyle`), analytics injection + `track()`, 3 loaders (Spin/Dots/Orbit) with 80 ms frames + 100 ms elapsed timer + `<progress>` for ready agents, intent matcher (price bounds, stemming, keyword→agent), scorer (brand 4 / title 2 / keyword 1 / category-word 1), landing + search renderers, per-click `asid` UUID + UTM stamping on `mousedown`+`click`, SW registration. |
| `sw.js` (15 lines) | Shell precache + stale-while-revalidate for all same-origin GETs incl. `data/*.json`; admin + cross-origin bypass. Public JS total = 119 lines ≤ 150. |
| `validate.js` | The one schema validator (browser global + Node `module.exports`), plus `agentFor()` (new-agent entry with emoji), `agentLI()`/`patchIndex()` (landing list template). |
| `agents.json` | 7 category indexes (shoes, clothing, electronics, home, beauty, sports, kids): `{id, name, category, products, stores, keywords}` — honest counts recomputed by the bot. |
| `llms.txt`, `openapi.json`, `.well-known/ai-plugin.json`, `opensearch.xml`, `robots.txt`, `sitemap.xml` | Agent-discovery layer. robots.txt explicitly welcomes GPTBot/ClaudeBot/PerplexityBot/Google-Extended/CCBot/… ; sitemap/robots/opensearch/openapi are regenerated by the feed agent from `SITE_URL`. |
| `data/*.json` | **96 real products** across 7 categories (13–19 each), 45 merchants — real photos (verified, square-cropped via each CDN), real prices and canonical product URLs, pulled by `scripts/build-catalog.mjs` from retailers' public endpoints (Shopify `products.json`, page JSON-LD/og meta). |
| `manifest.json`, `icon.svg`, `icon-192.png`, `icon-512.png` | Installable PWA (standalone, maskable). |
| `scripts/build-feed.mjs` + `.github/workflows/feed.yml` | Daily (06:17 UTC) + `workflow_dispatch` build-time feed agent: Skimlinks/Sovrn Product API when `SKIMLINKS_API_KEY` is set, fixtures otherwise; identical `validate.js`; refreshes `agents.json` store counts, auto-registers new categories, Amazon tag stamping, rewrites landing list; commits `data/`, `agents.json`, `index.html`. |
| `scripts/mock-github.mjs` | Dev-only mock of Contents GET/PUT, Commits, workflow_dispatch (with CORS + sha checks). |
| `scripts/build-catalog.mjs` | Dev tool: rebuilds the fixture catalog from live public retailer data (curated spec of stores/handles/regexes), verifies every image (browser UA, pixel dimensions), runs `validate.js`, writes `data/*.json`. |
| `README.md`, `DECISIONS.md`, `package.json`, `.gitignore` | Docs, decisions log, convenience scripts (no dependencies). |

## Verification performed (all passing)

* Landing renders 7 agents; `agent_view` event queued; no admin links; 0 style tags/attrs/stylesheets.
* Search: `white sneakers under $100` → 4 (price filter works), `sneakers` → 13, `nike` → 3 across all agents, `headphones under 200` → 3, `clothes`/`electronics`/`kids` → whole category, `coffee maker` → honest zero-results, `xyzzy` → zero-results state with 7 agent links, empty query → all 96 with Load more (24/48/72/96).
* Product links: `href` gains `utm_source=openshelf&utm_medium=referral&asid=<uuid>` on mousedown/click, new UUID per click, `outbound_click` event with `{merchant, brand, price, category, asid}`; `rel="sponsored noopener" target="_blank"`.
* Loader: all three variants cycle frames at 80 ms and tick elapsed at 100 ms; shown only around the real fetch, removed immediately after; SW-cached fetch = 1.6 ms so it never visibly appears on repeat searches.
* Speed: rank + render of an 850-product catalog ≈ 7 ms; first-load shell ≈ 14–18 KB excluding images.
* Lighthouse (mobile, headless Chrome): **index 100/100/100/100**, **search (results, empty, zero-results) Performance 100 / Accessibility 100** (Best-practices 96–100: one third-party cookie from a retailer image CDN; SEO 63 only because of intentional `noindex`), **admin 100/100/100**.
* Admin: malformed uploads (`bad.json` with bad price/currency/image/category + non-object row, `broken.json` non-JSON) rejected with row-level errors and no Publish button; `watches.json` (with a duplicate URL) → 4 valid, duplicate dropped, preview grid rendered, Publish → 3 mock commits (`data/watches.json`, `agents.json` with new ⌚ Watches Agent, `index.html` list sync), commit links shown, status board shows the new category with last-updated + commit, "Run bot now" → 204 dispatch.
* Feed agent: fixture mode writes all 7 files + agents.json + index.html; live mode tested against a stub API (good rows kept, garbage rows dropped, categories under `FEED_MIN` or HTTP 500 keep the previous file; exit 1 only when every live category fails).
* Mobile viewport (375 px): 2-column grid fits (scrollWidth = viewport, no horizontal scroll).
* Visual audit of all product photos via a contact sheet — every image matches its product (entries with unverifiable ids were removed).

## How to run

```bash
python3 -m http.server 8765      # then open http://localhost:8765
node scripts/build-catalog.mjs   # rebuild fixture catalog from live retailer data (verifies images)
node scripts/build-feed.mjs      # daily bot path (fixtures unless SKIMLINKS_API_KEY is set)
node scripts/mock-github.mjs     # mock GitHub API for admin.html (API base http://127.0.0.1:8766)
```

## How to deploy

Push the folder to a GitHub repo → enable **GitHub Pages** (branch `main`, root) *or* connect the repo to **Cloudflare Pages / Netlify** with no build command. No files change between hosts. Full steps, admin protection (Cloudflare Access / Netlify password), Capacitor wrap and store checklist are in `README.md`.

## Decisions

All 26 recorded in `DECISIONS.md` — highlights: real-data fixture catalog (placeholders rejected); Skimlinks/Sovrn as the real feed source with fixture fallback; bot drops invalid rows while human uploads are strict (same validator); static landing list generated from `agents.json` (CLS 0); `search.html` stays `noindex`; disclosure moved above results (CLS 0); SW bypasses `admin*`; Plausible on by default (skipped on localhost), GA4/Skimlinks off until ids set; asid stamped on mousedown + click; "Run bot now" needs Actions: read/write on the PAT.

## Your next manual steps

1. **Create the repo & deploy** — `git init && git add -A && git commit -m "OpenShelf"` → push → enable Pages (or Cloudflare/Netlify). Set repo *variables* **`SITE_URL`** (deployed origin; regenerates sitemap/robots/opensearch/openapi with absolute URLs — run the feed workflow once), `AMAZON_ASSOCIATE_TAG`, optional `SKIMLINKS_PRODUCT_API`, `FEED_COUNTRY`; repo *secret* `SKIMLINKS_API_KEY` when you have it. Note the workflow needs *Settings → Actions → General → Workflow permissions: Read and write*.
2. **Protect `/admin.html`** — Cloudflare Access application on path `admin*` (or Netlify visitor access). Then create the fine-grained PAT (this repo only; Contents: read/write; Actions: read/write for the bot button), open `/admin.html`, save Owner/Repo/Branch + token.
3. **Plausible** — create the site at plausible.io with your domain (matches `location.hostname`), add custom-event goals `search`, `outbound_click`, `zero_results`, `agent_view` and enable custom properties `query`, `category`, `merchant`, `brand`, `results`, `asid`. If your domain differs from the served hostname, set `CFG.plausible` explicitly. (GA4: set `CFG.ga4`.)
4. **Affiliate signups** — Sovrn Commerce (Skimlinks): register, add domain, paste publisher id into `CFG.skimlinks`; ask for Product API access → `SKIMLINKS_API_KEY`. Amazon Associates: get your tag → `AMAZON_ASSOCIATE_TAG`; the bot rewrites the placeholder `openshelf-20`. Optionally CJ/Rakuten: add a fetcher in `scripts/build-feed.mjs`.
5. **Catalog refresh** — `npm run catalog` re-pulls the fixture catalog from the same public endpoints (prices/images drift); enable the feed keys for the nightly bot; or upload your own `<category>.json` files through the admin page.
6. **Capacitor store builds** — follow the README section (`npx cap init … && npx cap add ios && npx cap add android`, `server.url` = your deployed URL), replace the generated icons with real artwork (1024² / 512²), take screenshots, fill the privacy forms, submit. Everything works with zero code changes to this repo.
