# DECISIONS.md — calls made during the autonomous build

| # | Decision | Rationale |
|---|---|---|
| 1 | Fixture catalog is built from **real, public retailer data** by `scripts/build-catalog.mjs`: Shopify stores' public `/products.json` (Everlane, Glossier, Casper, Kith, Manduka, Radio Flyer, …) and product pages' JSON-LD/og image + price meta (Nike, Puma, Converse, IKEA, KitchenAid, Garmin, …). Every image URL is verified to return an image and requested as a 352×352 square via each CDN's transform, so `<img width=160 height=160>` never distorts. | First attempt used picsum placeholders — rejected by the owner ("all the images are incorrect"). Wikipedia/Commons search was tried and produced logos/celebrities, so accuracy came from retailer sources only; entries whose product ids couldn't be verified (J.Crew, Samsung, Target/Apple, Uniqlo) were dropped after a visual audit. |
| 2 | Real feed source = **Skimlinks / Sovrn Commerce Product API**, endpoint + key via env (`SKIMLINKS_PRODUCT_API`, `SKIMLINKS_API_KEY`), tolerant field mapping. No key present → fixtures (demo mode). | Spec asked for one real source + fixtures; Skimlinks is also the click-time monetisation layer, so one signup covers both. Field names vary by API version, hence the tolerant mapper + configurable endpoint. Tested against a stub server (good rows, garbage rows, HTTP 500). |
| 3 | Bot path drops *invalid rows* from a live feed and publishes the valid remainder (min `FEED_MIN`=5, else keeps the previous file). Human upload path in admin.html is strict: any error → no Publish button. | Both use the identical `validate.js`, so nothing invalid is ever published either way; a human can fix rows, a cron job can't. |
| 4 | `validate.js` is a UMD-style classic script (`module.exports` in Node, globals in browser). Node scripts are `.mjs` and load it via `createRequire`. | One file, no bundler, works in `<script src>` and in GitHub Actions unchanged. |
| 5 | Landing "Agents ready" `<ul>` is rendered **statically** into `index.html` from `agents.json` (markers `<!-- agents:start/end -->`) by the feed agent and by admin publishes; `app.js` re-renders only if `agents.json` differs (fingerprint `id:stores`). | Removed the only layout shift on the landing page → Lighthouse Performance 100 with CLS 0. `agents.json` stays the single source of truth. |
| 6 | Search page keeps `<meta name="robots" content="noindex">` (Lighthouse SEO shows 63 because of it). | Infinite `?q=` URLs shouldn't be indexed; SEO score wasn't a target, Performance/Accessibility were (both 100). Remove the meta if you want query pages indexed. |
| 7 | Disclosure text on `search.html` sits in the header (above results) instead of a footer. | A footer below the dynamic results area moved when the loader was replaced → CLS 0.10; moving it gave CLS 0 and Performance 100. |
| 8 | Service worker: SWR for every same-origin GET keyed by path (so `search.html?q=…` shares one cache entry); `admin*` bypasses the SW; cross-origin always network. | Instant repeat searches + offline tolerance; admin must never see stale JS. |
| 9 | Plausible loads by default with `data-domain = location.hostname`; skipped on localhost/127.x. GA4 and Skimlinks are off until an id is set in `CFG`. | Speed-first defaults; no third-party bytes in local/Lighthouse runs, one-line enable. |
| 10 | asid/UTM stamping happens on `mousedown` **and** `click` (idempotent per click, new UUID after each click). | `mousedown` runs before Skimlinks' click-time link rewriting so the params survive; `click` covers keyboard activation. |
| 11 | "Run bot now" needs the PAT to also have **Actions: read/write**; Contents: read/write alone covers upload/publish. | `workflow_dispatch` is under the Actions permission on fine-grained tokens. Documented in README + admin page. |
| 12 | Admin status board reads `agents.json`/`data/*.json` from the **repo via API** when a repo is configured (else from the deployed site). | Newly published categories show immediately, before the host redeploys. |
| 13 | Icons are PNGs generated with a dependency-free Python snippet + an SVG favicon. | No design tooling available; PWA installability needs 192/512 PNG. Replace with real artwork before store submission. |
| 14 | `ALLOW_LOADER_STYLE` (`CFG.allowLoaderStyle`) is `false`; when true a `<style>` element is created via `document.createElement` (never as markup). | Keeps every HTML file free of any `<style`/`style=` string; the shimmer is opt-in only. |
| 15 | The bot stamps `tag=<AMAZON_ASSOCIATE_TAG>` on any Amazon URL it writes (the current real-data catalog contains none). | Wiring is ready; the real tag only exists after Associates signup. |
| 16 | `scripts/mock-github.mjs` is committed (dev-only) and its state dir `.mock-github` is git-ignored. | The admin publish flow was tested end-to-end against it; keeping it lets you re-test without a token. |
| 17 | 7 agents / 85 products / 61 distinct merchants in fixtures (spec: 5–7 agents, ≥60 products). Store counts in `agents.json` are computed from the data (honest counts). | Enough coverage for meaningful demo queries incl. price bounds and zero-results. |
| 18 | Category-word tokens (e.g. "clothes", "electronics") add +1 to every product of that agent so category-only queries return the whole category instead of zero. | Users type categories as often as products. |
| 19 | Search results are limited to `pageSize` = 24 per batch; "Load more" is a plain `<a>` handled by JS. | Spec; keeps DOM small and lazy images effective. |
| 20 | No `package.json` dependencies at all; `package.json` only carries convenience scripts. | Zero frameworks/bundlers; `npm i` is a no-op. |
| 21 | Product card = `<td width="50%" align="center" valign="top">` inside `<table width="100%" cellpadding="6" cellspacing="0">`: image (160×160) over **Brand** / title / **price** on three centred lines. | Owner disliked the first single-line layout. Presentational HTML *attributes* (`width`, `align`, `valign`, `cellpadding`) are not CSS, so the zero-CSS rule holds; 160px images keep two columns inside a 375px phone without horizontal scroll. |
| 22 | Service worker revalidates with `fetch(req, {cache:'no-cache'})`. | Otherwise the SW re-populates its cache from the browser's HTTP cache after a deploy and shoppers can keep the previous app.js for a long time. |
| 23 | Only *generic* words (agent category/id + the first two keywords of each agent) give the whole-category bonus; specific words like "coffee" or "lego" must appear in a product. | Prevents "14 matches for coffee maker" when no coffee maker exists. Documented in a `_note` field inside `agents.json`. |
| 24 | Renamed to **OpenShelf — the product index for AI agents**; all copy addresses agents (query once instead of crawling hundreds of stores; JSON or HTML; no key). Sub-indexes are named `<Category> Index`. `utm_source=openshelf`. | Owner: the site's consumers are agents, not humans; "Agent Shop" read as a shop *run by* agents. |
| 25 | Zero emojis anywhere (UI, admin, agents.json, icon); the Braille spinner frames are Unicode symbols, not emoji, and stay because the loader spec requires them. "How it works" `<details>` removed; the FTC disclosure moved to the footer. | Owner request. |
| 26 | Agent-discovery layer: `robots.txt` (AI crawlers explicitly allowed + Sitemap), `sitemap.xml`, `llms.txt`, `openapi.json` (OpenAPI 3.1 for agents.json / data/{category}.json / search.html), `.well-known/ai-plugin.json`, `opensearch.xml`, JSON-LD `WebSite`+`SearchAction` and `DataCatalog`/`Dataset` per category, `<link rel=alternate>` to JSON/OpenAPI/llms.txt, `<link rel=search>`, full meta/OG/audience tags, `search.html` no longer `noindex`. Files needing absolute URLs are generated by the feed agent from the `SITE_URL` variable (placeholder `https://openshelf.example` until set). | So crawlers, LLM agents and plugin/tool loaders can discover the JSON endpoints and the search action without reading the HTML. `<link rel=canonical>` omitted until `SITE_URL` is known (must be absolute). |
| 27 | Admin dashboard removed (owner request); the daily GitHub Action now runs the collector `build-catalog.mjs` (retailer public endpoints, curated picks + newest matching products, `COLLECT_TOP`) followed by `build-feed.mjs`, and commits. Thin runs (< 60 % of previous count or < 5) keep the previous category file. | Owner wants zero-touch daily collection, no manual uploads. Same `validate.js` gate remains. |
