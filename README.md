# OpenShelf — the product index for AI agents

A **100 % static site** — no backend, no server, no database, **zero CSS** — whose consumers are AI agents, shopping bots and LLM assistants. Instead of crawling hundreds of retailer sites, an agent queries OpenShelf once and gets brand, title, price, image and a direct retailer URL for every match, as HTML (`search.html?q=`) or plain JSON (`agents.json`, `data/{category}.json`). Clicking/following a product goes to the retailer with tracking parameters; the retailer does sizes, colours, cart, checkout.

```
index.html      landing: query box, category indexes (static, generated from agents.json), endpoint table, JSON-LD WebSite/SearchAction + DataCatalog
llms.txt · openapi.json · opensearch.xml · robots.txt · sitemap.xml · .well-known/ai-plugin.json   agent-discovery layer (the last four are generated by the feed agent from SITE_URL)
search.html     results: client-side intent matcher → fetch data/<category>.json → rank → 2-column <table> grid
admin.html      owner-only dashboard (unlinked, noindex): upload → validate → preview → publish via GitHub API
app.js          the whole public-side app (~100 lines): intent, ranking, grid, loaders, analytics, asid stamping
admin.js        dashboard logic (exempt from the 150-line budget, dependency-free)
validate.js     THE product-schema validator, shared by admin.html (browser) and the feed agent (Node)
agents.json     category index — single source of truth for landing + search + admin + bot ({id,name,category,products,stores,keywords})
data/*.json     one file per category: [{brand,title,price,currency,image,url,merchant,category,keywords}]
manifest.json   PWA manifest · sw.js  service worker (shell precache + stale-while-revalidate for /data)
scripts/build-feed.mjs   build-time feed agent (Skimlinks/Sovrn Product API → validate → write data/, agents.json, index.html)
scripts/build-catalog.mjs  builds the fixture catalog from real public retailer endpoints (Shopify products.json, page JSON-LD/og) — dev tool
scripts/mock-github.mjs  local mock of the GitHub endpoints admin.html uses (dev/test only)
.github/workflows/feed.yml   daily cron + workflow_dispatch ("Run bot now")
```

## Run locally (demo mode, zero keys)

```bash
python3 -m http.server 8765
```

Open <http://localhost:8765>. Try `white sneakers under $100`, `headphones under $200`, `lego`, `xyzzy` (zero-results state).
Everything runs from the committed fixtures — 96 real products (real photos, prices and canonical product URLs pulled from retailers' public endpoints by `npm run catalog`), 7 categories, 45 merchants. Nothing needs an API key.

Optional: `npm run catalog` (rebuild the fixture catalog from live retailer data — verifies every image), `npm run feed` (daily bot: refresh from your feed keys / re-validate fixtures), `npm run mock-github` (mock API for the admin page).

## Deploy (unchanged files, free tier)

| Host | Steps |
|---|---|
| **GitHub Pages** | Settings → Pages → Source: *Deploy from a branch* → `main` / `/ (root)`. Done. The feed Action commits to `main`, so Pages redeploys after every bot run. |
| **Cloudflare Pages** | Create project → connect repo → Framework preset *None*, build command *(empty)*, output dir `/`. |
| **Netlify** | New site from Git → build command *(empty)*, publish dir `.` |

The site is path-relative (`./`, `data/…`, `sw.js`), so it works at a domain root **or** under `/repo-name/`.

### After deploy

Set the repo variable **`SITE_URL`** to your deployed origin and run the feed workflow once (or `SITE_URL=https://… node scripts/build-feed.mjs`) so `sitemap.xml`, `robots.txt`, `opensearch.xml` and `openapi.json` carry absolute URLs; optionally add `<link rel="canonical">` tags. Then 3 config lines in `app.js`:
```js
plausible: location.hostname, // Plausible data-domain (default = your host). '' disables.
ga4: '',                      // 'G-XXXXXXX' to enable GA4 (optional alternative / addition)
skimlinks: '',                // your Skimlinks publisher id → loads s.skimresources.com/js/<id>.skimlinks.js
```

## How the agents work (no backend)

* **Build-time agent** — `scripts/build-feed.mjs`, run daily by `.github/workflows/feed.yml`. With `SKIMLINKS_API_KEY` set it queries the Skimlinks / Sovrn Commerce Product API per agent category; without keys it keeps the committed fixtures (demo mode). Everything passes through `validate.js`; invalid rows are never written; if a whole category comes back bad the previous file is kept. It also refreshes store counts in `agents.json`, auto-registers agents for new `data/*.json` files, stamps `tag=<AMAZON_ASSOCIATE_TAG>` on Amazon URLs, and rewrites the static "Agents ready" list in `index.html` (between `<!-- agents:start/end -->`).
* **Client-side agent** — on `search.html?q=…`, `intent()` extracts price bounds (`under $100`, `over 50`, `20-50`), stems tokens, maps keywords → agents via `agents.json`; the matching category files are fetched (SW-cached after first load), `score()` ranks brand > title > keyword hits, price filter applied, first 24 rendered, "Load more" appends the next batch. Honest counts: "1 index searched, 6 stores, 13 products — 4 matches", plus links to the raw JSON of the searched categories.
* **Loading state** — Braille spinner + elapsed time + "ready" agents with native `<progress>`; three variants (`spin`/`dots`/`orbit`, `CFG.loader`). Shown only around the real fetch, removed the instant results render. On SW-cached repeat searches it flashes for ~2 ms — that's the design working.

## Admin dashboard (`/admin.html`)

> **Obscurity is not privacy.** The page is unlinked and `noindex`, but anyone who guesses the URL can load it. It is *inert* without your token, but still protect it:
> * **Cloudflare Pages** → Zero Trust → Access → Applications → *Add an application* → Self-hosted → domain `yoursite.pages.dev`, path `admin*` → policy *Allow* → *Emails* = your address. Free for up to 50 users.
> * **Netlify** → Site configuration → Access & security → *Visitor access* → password-protect the whole site, or (Pro) add a `_headers` rule `Basic-Auth` scoped to `/admin*`.
> * **GitHub Pages** has no access control — put Cloudflare in front of it, or host on Cloudflare/Netlify.

Setup:
1. GitHub → Settings → Developer settings → **Fine-grained personal access tokens** → *Generate new token* → Resource owner = you → **Only select repositories** = this repo → Permissions: **Contents: Read and write** (+ **Actions: Read and write** if you want the "Run bot now" button; + Metadata: read is added automatically). Set an expiry.
2. Open `/admin.html`, fill Owner / Repo / Branch, paste the token, **Save**. It is stored in `localStorage` in plain text on that browser only; the **Forget token** button removes it.
3. **Upload** one or more `<category>.json` files (filename = category, e.g. `watches.json`). Each is validated with `validate.js`: JSON parses, every record has `{brand,title,price,currency,image,url,merchant,category,keywords}`, price is a positive number, currency is ISO-3, URLs are absolute http(s), duplicates by `url` are dropped. Errors are shown row-by-row; a file with any error has no Publish button.
4. **Preview** — the first 10 valid products are rendered with the very same `cell()` template `search.html` uses.
5. **Publish** — one button per file → `PUT /repos/{owner}/{repo}/contents/data/<category>.json` with message `admin: update <category>.json (N products)`; the commit link is shown. New categories are auto-registered in `agents.json` (emoji picked from a table, `🛍️` fallback), and the landing list in `index.html` is re-synced. The host redeploys in ~1 minute.
6. **Status board** — per category: product count, merchant count, last-updated + commit link (Commits API), plus a link to your Plausible dashboard. **Run bot now** fires `workflow_dispatch` on `feed.yml`.

The daily bot writes the same files with the same schema through the same validator, so switching from manual uploads to the bot is just leaving the cron on.

Test the whole flow without a real repo: `npm run mock-github` → in admin.html set *API base* to `http://127.0.0.1:8766` and any non-empty token.

## For agents (discovery layer)

* `llms.txt` — plain-text instructions: fetch `agents.json`, then `data/{category}.json`, filter locally, follow `url` with `utm_source=openshelf&utm_medium=referral`.
* `openapi.json` (OpenAPI 3.1) + `.well-known/ai-plugin.json` — machine-readable description of the three endpoints, no auth.
* `robots.txt` explicitly allows GPTBot, ClaudeBot, PerplexityBot, Google-Extended, CCBot, Applebot-Extended, Amazonbot, meta-externalagent, etc., and points at `sitemap.xml`, `llms.txt`, `openapi.json`.
* `opensearch.xml` (`<link rel=search>`), JSON-LD `WebSite`+`SearchAction` and a `DataCatalog` with one `Dataset` per category (regenerated with the catalog), `<link rel=alternate>` to JSON/OpenAPI/llms.txt, `meta name=audience`, OG/Twitter tags. `search.html` is indexable and has a `<noscript>` pointer to the JSON path.

## Tracking & analytics (all client-side)

* Every outbound click gets `utm_source=openshelf&utm_medium=referral&asid=<crypto.randomUUID()>` stamped at click time (mousedown + click, so it precedes affiliate rewriting) — your traffic proof for direct retailer deals.
* Plausible events: `search {query, category, results}`, `outbound_click {merchant, brand, price, category, asid}`, `zero_results {query, category, results:0}`, `agent_view {agents}`. Configure the goals in Plausible → Site settings → Goals → *Custom event*, and mark `query`, `merchant`, `category` as custom properties.
* GA4: set `CFG.ga4 = 'G-…'` and the same events fire via `gtag`.
* Skimlinks/Sovrn dashboard = independent per-merchant click + commission report.

## Affiliate signup steps

1. **Skimlinks / Sovrn Commerce** — <https://www.sovrn.com/publishers/commerce/> → sign up as publisher → add your domain → copy the publisher id from the JS snippet (`https://s.skimresources.com/js/<id>.skimlinks.js`) into `CFG.skimlinks`. Approval usually takes a few days; links work as plain retailer links until then. For the Product API, request access from your Sovrn account manager and put the key in the repo secret `SKIMLINKS_API_KEY` (and endpoint in the repo variable `SKIMLINKS_PRODUCT_API` if yours differs from `https://api-products.skimlinks.com/query`).
2. **Amazon Associates** — <https://affiliate-program.amazon.com/> → get your tag (e.g. `yourname-20`) → repo variable `AMAZON_ASSOCIATE_TAG`. The current real-data catalog has no Amazon URLs; when a feed supplies them, the bot stamps your tag.
3. **CJ / Rakuten** — optional; add a second fetcher in `scripts/build-feed.mjs` mapping their fields into the same schema; `validate.js` guards the rest.
4. Keep the FTC disclosure (footer of `index.html`, header of `search.html`) and `rel="sponsored"` on every product link (already generated).

## PWA

`manifest.json` (standalone, icons 192/512 PNG + SVG, maskable) + `sw.js`: precaches the app shell on install; every same-origin GET (including `data/*.json`) is served **stale-while-revalidate** — instant repeat searches, offline-tolerant. Cross-origin (product images, analytics) and `admin*` are always network. Bump `CACHE` in `sw.js` to force a refresh.

## Wrap as iOS / Android apps with Capacitor (zero code changes)

```bash
mkdir agent-shop-app && cd agent-shop-app && npm init -y
npm i @capacitor/core @capacitor/cli @capacitor/ios @capacitor/android
npx cap init "OpenShelf" com.yourco.openshelf --web-dir www
mkdir www && echo '<meta http-equiv="refresh" content="0;url=https://YOUR-DEPLOYED-URL/">' > www/index.html
```
Edit `capacitor.config.json` so the app loads the live site (the PWA + SW keep it fast/offline-tolerant):
```json
{ "appId": "com.yourco.openshelf", "appName": "OpenShelf", "webDir": "www",
  "server": { "url": "https://YOUR-DEPLOYED-URL", "cleartext": false } }
```
```bash
npx cap add ios && npx cap add android
npx cap open ios      # Xcode → set Team → Product → Archive → Distribute
npx cap open android  # Android Studio → Build → Generate Signed Bundle (.aab)
```
Outbound `target="_blank"` links open in the system browser inside the Capacitor webview, so retailer checkout works. Plausible works inside webviews (no cookies).

## Constraints kept

Zero CSS (`grep -rEn '<style|style=|stylesheet|\.css' *.html app.js` → nothing; layout uses only HTML attributes such as `width`/`align`/`cellpadding`) · zero backend · public JS = `app.js` (~104 lines) + `sw.js` (15) ≤ 150 · first load ≈ 17 KB (HTML + JS + JSON + manifest, no images) · Lighthouse mobile: Performance 100 / Accessibility 100 on landing and search · rank + render 850 products ≈ 7 ms.
